# 3D Post-Processor Design — Relief Toolpath to GRBL G-code

**SPK-0707 · Phase H (v1.1)** · Created: 2026-07-28

---

## Overview

The 3D post-processor converts relief toolpaths generated by the CAM engine into GRBL-compatible G-code for CNC routers. It handles both roughing (stock removal) and finishing (surface contouring) passes, producing safe, efficient code that respects GRBL's motion model — linear interpolation only, no arcs in 3D space, and strict Z-axis safety rules.

The post lives inside `ShopPilotCore` alongside the existing 2D post-processor, sharing a common base class but diverging on Z-depth handling, feed-rate strategies, and arc-segmentation of curved toolpaths.

---

## 1. Converting 3D Toolpaths to GRBL G-code

### 1.1 Input model

The CAM engine produces a `Toolpath` containing:
- **Cut segments**: ordered list of (X, Y, Z) waypoints with associated feed rate and cutter radius. Each segment is already linearized from the original curve (NURBS or arc) into short line segments — typically 0.01–0.1 mm chordal tolerance.
- **Roughing passes**: stepped Z-levels removing bulk material down to a finish allowance (e.g., 0.25 mm). Uses a zigzag or offset pattern with climb milling direction.
- **Finishing passes**: follows the exact relief surface at the final Z-depth, using side-skip or step-over patterns matching the desired surface finish.

### 1.2 Output format

GRBL does not support G2/G3 arcs in 3D (only XY plane). Therefore all curved toolpath segments must be pre-linearized by the CAM engine before reaching the post. The post's job is purely translation:

```
G0 Z5.0          ; safe retract height
G0 X10.0 Y20.0   ; rapid to start position (Z stays at safe height)
G1 Z-0.75 F80    ; plunge to cutting depth
G1 X12.3 Y21.8 Z-0.82 F200  ; cut segment with interpolated Z
G1 X14.6 Y23.1 Z-0.91 F200
...
G0 Z5.0          ; retract after pass complete
```

### 1.3 G-code structure per toolpath

Each toolpath generates a self-contained block:

| Section | Commands | Purpose |
|---------|----------|---------|
| Header | `G20`/`G21`, `G90`, comments | Units, absolute mode, metadata |
| Setup | `G54` WCS, spindle start (M3), coolant (M8) | Coordinate system and machine state |
| Roughing | G0/G1 blocks at stepped Z levels | Bulk material removal |
| Finishing | G1 blocks following surface contour | Final surface pass |
| Cleanup | Spindle stop (M5), retract, end-of-program (M2) | Safe shutdown |

### 1.4 Coordinate system

- **Absolute positioning** (`G90`) throughout — no relative moves in relief toolpaths.
- Work coordinate `G54` is the default; the post can be configured for other WCS offsets if needed.
- All coordinates are output in the job's selected units (mm or inches), matching the machine profile setting.

## 2. Z-depth Moves: G0 Rapid vs G1 Feed

### 2.1 The safety rule

**Never rapid through material.** A G0 rapid move with simultaneous X/Y and Z motion can crash the bit into the workpiece if the Z clearance is insufficient. The post enforces a two-step Z strategy:

```
Safe approach (above stock):
  G0 Z5.0          ; rapid to safe height
  G0 X10.0 Y20.0   ; rapid to XY position (Z unchanged)
  G1 Z-0.75 F80    ; controlled plunge to cut depth

Safe retract (above stock):
  G1 Z5.0 F200     ; feed up to safe height first
  G0 X14.6 Y23.1   ; then rapid XY move
```

### 2.2 Decision matrix

| Scenario | Move type | Rationale |
|----------|-----------|-----------|
| Z above stock, moving to new XY position | **G0** (rapid) | No collision risk; fastest traverse |
| Z at or below surface, changing X/Y | **G1** (feed rate) | Bit is cutting — must follow toolpath feed |
| Plunging from safe height into material | **G1** (plunge rate) | Controlled entry prevents bit breakage |
| Retracting from cut depth to safe height | **G1** (cut/feed rate or faster) | Can be faster than plunge since no cutting force |
| Z-only move within cut zone (step-down between roughing levels) | **G1** (plunge rate) | Conservative — bit may still be engaged with material below |

### 2.3 Safe height configuration

The safe retract height is a job-level parameter, typically:
- **Air cut clearance**: 3–5 mm above the highest point of the relief surface
- **Material thickness offset**: stored in the `Job` document and passed to the post at generation time
- The post outputs this as the initial Z position after spindle start

### 2.4 Z-only moves during roughing

Between roughing step-downs, the tool may need to retract slightly before stepping deeper (to clear chips). This is a G1 move at plunge rate — never G0:

```
; End of roughing pass at Z-0.5
G1 Z3.0 F150    ; retract above surface
G1 Z-0.75 F80   ; step down to next level (plunge rate)
G1 X... Y...    ; resume cutting
```

## 3. Feed Rate Strategies for 3D Cutting

### 3.1 Three distinct feed rates

| Rate | Symbol in G-code | Typical range (wood, 6mm endmill) | When used |
|------|------------------|-----------------------------------|-----------|
| **Plunge rate** | `F` on Z-only G1 moves into material | 50–120 mm/min | Entering stock, step-downs between levels |
| **Cut (profile) rate** | `F` on X/Y/Z simultaneous G1 moves | 150–400 mm/min | Actual surface cutting during finishing |
| **Rapid traverse** | implicit in G0 | 2000–6000 mm/min | Non-cutting XY moves above safe height |

### 3.2 Plunge rate rationale

Plunge rate is the slowest because:
- The bit's tip geometry (flat endmill, ball nose) creates a zero-surface-speed condition at center — material is being squeezed rather than sheared.
- Chip evacuation is poorest in the Z direction; chips pack around the flutes.
- Bit breakage risk is highest during entry.

The post applies plunge rate to:
1. Initial entry from safe height into first cut depth
2. Step-downs between roughing levels (even when not cutting at that exact Z)
3. Any Z-only move where material exists below the current Z position

### 3.3 Cut rate for finishing passes

Finishing feed rates are determined by:
- **Cutter diameter**: smaller bits → lower feed (less rigidity, less chip capacity)
- **Step-over percentage**: tighter step-overs increase cutting load → reduce feed slightly
- **Material hardness**: softwoods vs hardwoods vs plastics
- **Surface finish target**: finer finishes may use higher RPM with moderate feed

The post receives the cut rate from the toolpath engine as a property on each segment, allowing per-segment variation if the CAM engine computes adaptive rates based on local engagement angle.

### 3.4 Roughing feed strategy

Roughing uses a compromise between speed and tool life:
- **Cut rate**: typically 60–80% of finishing cut rate (more aggressive stock removal)
- **Step-down per pass**: determined by the bit's axial depth-of-cut rating (e.g., 1.5× diameter for softwood, 0.5× for hardwood)
- The post outputs each roughing level as a separate Z-block with G1 moves at the roughing cut rate

### 3.5 Spindle speed synchronization

Spindle RPM is set once at toolpath start and remains constant throughout:

```
M3 S8000          ; spindle on, 8000 RPM clockwise
; ... all cutting moves use F values only, no S re-specification ...
M5                ; spindle stop (at end of program)
```

The post does not vary spindle speed mid-toolpath. Variable spindle control (if needed for adaptive feed) would require M3/S commands between segments — a future enhancement.

## 4. Integration with the Existing 2D Post System

### 4.1 Shared base class

Both 2D and 3D posts inherit from a common `GRBLPostProcessor` base:

```
GRBLPostProcessor (base)
├── Header/footer generation (units, WCS, comments)
├── Safe height management
├── G0/G1 emission helpers
├── Spindle/coolant command sequencing
└── Line buffering + character-count streaming support

2DPostProcessor (extends base)
├── Profile, pocket, V-carve strategies
├── Z-move handling: simple plunge/retract only
└── No interpolated Z in cutting moves

3DPostProcessor (extends base)
├── Roughing pass emission with stepped Z levels
├── Finishing pass emission with G1 Z interpolation
├── Plunge vs cut rate selection logic
└── Arc-linearization verification (asserts segments are pre-linearized)
```

### 4.2 What the base class handles

The shared base manages everything that is identical between 2D and 3D posts:
- **G-code header**: `G20`/`G21`, `G90`, job metadata comments (material, tool info, timestamp)
- **WCS selection**: outputs `G54` (configurable)
- **Spindle sequencing**: M3/M4 with RPM, M5 stop — always before first cut, after last cut
- **Coolant**: M8 flood / M7 mist, configurable per machine profile
- **Safe height**: stored in the post config; used for all G0 Z moves and initial positioning
- **Footer**: `M2` end-of-program marker

### 4.3 What diverges in the 3D post

The 3D post adds:
1. **Z-interpolation logic**: emits G1 with X, Y, and Z coordinates simultaneously for each segment of a finishing pass. The base class only handles G0 (Z-only retract) and G1 (Z plunge + XY cut).
2. **Feed rate selection**: the 3D post chooses between plunge rate and cut rate based on whether the move is Z-engaging or surface-following. The 2D post uses a single feed rate for all cutting moves.
3. **Roughing pass structure**: emits multiple Z-level blocks with retracts between levels, each containing its own set of XY cutting segments.
4. **Segment validation**: asserts that incoming toolpath segments are linear (no arcs) and within GRBL's coordinate limits.

### 4.4 Toolpath engine interface

The CAM engine calls the post through a unified protocol:

```swift
protocol PostProcessor {
    func emitHeader(job: Job, tool: CuttingTool) -> [String]
    func emitSegments(segments: [CutSegment], feedRate: Double, plungeRate: Double?) -> [String]
    func emitFooter() -> [String]
}
```

For 2D toolpaths, `plungeRate` is nil (single rate used). For 3D toolpaths, both rates are provided and the post selects between them per-segment. This keeps the interface identical while allowing different internal behavior.

### 4.5 Output pipeline

```
Toolpath Engine → [CutSegment] array → PostProcessor.emitSegments() → [String] G-code lines
                                                                        ↓
                                                              ShopPilotCore.GCodeDocument
                                                                        ↓
                                                          User review in Job Console
                                                                        ↓
                                              SerialTransport.write() or file save
```

The post produces an array of G-code strings (one per line). These are collected into a `GCodeDocument` that the UI presents for review before streaming. This is identical to the 2D flow — no architectural change needed in the downstream pipeline.

### 4.6 Fixture and test strategy

- **Golden fixtures**: pre-computed G-code files for known relief geometries (sphere, pyramid, custom profile) with checksums for regression testing.
- **Air-cut safe**: all fixture toolpaths stay above Z=0 so they can be run on any machine without material contact.
- **Unit tests**: verify that every Z-only move into material uses G1 at plunge rate, and every XY traverse above safe height uses G0.

## Open Questions

1. **FluidNC arc support**: FluidNC 3.x supports G2/G3 in the XY plane. Should the post emit arcs for finishing passes where the CAM engine can produce them efficiently? (Deferred — linearization is safer for GRBL v1.1 compatibility.)
2. **Spindle ramp-up time**: should the post insert a dwell (`G4 P2`) after M3 before the first cut move? (Recommended for large bits; configurable in machine profile.)
3. **Chip-clear pauses**: should roughing passes include periodic G0 retract + dwell to clear chips from deep pockets? (Configurable per-material setting.)
